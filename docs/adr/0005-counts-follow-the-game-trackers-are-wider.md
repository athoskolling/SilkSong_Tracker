# Counts follow the game, Trackers are wider, and Rosaries come from prices on entries

The headline completion numbers count only what the game itself counts toward 100 percent, while the Trackers also follow things the game does not count (Mementos, Equipment). We mark those as Collectibles with `counts: false` rather than add a third `kind`. That way every existing screen, check and test that reads `kind` keeps its meaning, the current data needs no edit, and a Memento stays a thing the player obtains, not a Task. Counting the wider set in the headline was rejected because the number would stop matching the game's own 100 percent, which is what a completion run is measured against.

For Rosaries, shop entries carry a `price` and the player marks them done when bought; the amount still to spend is worked out from the prices of entries not done. Storing a typed Rosaries number in Progress was rejected (Athos, 2026-10-20). Numbers cannot be merged by union, so ADR 0001 would have needed a "newer value wins" exception and the sync code would have needed new tests. A number the player retypes also goes stale the moment they spend in the game. Keeping Progress as ids only leaves union merge, import, export and the Firestore rules untouched. The cost is that the site cannot show how many Rosaries the player is holding, only what the guide still expects them to spend.

Note (2026-10-20): ADR 0006 later added three optional player choices to Progress (opened Crest slots, saved Builds and, provisionally, a typed Shell Shards number). Rosaries are still not a number in Progress; this decision stands.
